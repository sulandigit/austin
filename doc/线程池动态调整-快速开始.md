# 线程池动态调整 - 快速开始

## 前置条件

1. 项目已成功启动
2. Apollo 配置中心已配置(如使用配置中心方式)
3. 已有动态线程池注册到系统中

## 5分钟快速体验

### 1. 查看所有线程池

访问 Swagger 文档:
```
http://localhost:8080/swagger-ui/index.html
```

或直接调用接口:
```bash
curl http://localhost:8080/threadPool/list
```

### 2. 查看单个线程池详情

```bash
curl http://localhost:8080/threadPool/get/execute-xxl-thread-pool
```

返回示例:
```json
{
  "status": "success",
  "msg": "success",
  "data": {
    "threadPoolName": "execute-xxl-thread-pool",
    "corePoolSize": 3,
    "maximumPoolSize": 3,
    "queueCapacity": 200,
    "queueType": "VariableLinkedBlockingQueue",
    "rejectedHandlerType": "CallerRunsPolicy",
    "keepAliveTime": 50,
    "allowCoreThreadTimeOut": false,
    "activeCount": 0,
    "poolSize": 0,
    "largestPoolSize": 0,
    "completedTaskCount": 0,
    "queueSize": 0,
    "queueRemainingCapacity": 200,
    "rejectCount": 0
  }
}
```

### 3. 动态调整线程池参数

```bash
curl -X POST http://localhost:8080/threadPool/adjust \
  -H "Content-Type: application/json" \
  -d '{
    "threadPoolName": "execute-xxl-thread-pool",
    "corePoolSize": 5,
    "maximumPoolSize": 10,
    "keepAliveTime": 60
  }'
```

### 4. 验证调整结果

再次查询线程池信息，确认参数已生效:
```bash
curl http://localhost:8080/threadPool/get/execute-xxl-thread-pool
```

## 配置监控告警

### 1. 配置钉钉机器人

在 `dynamic-tp-apollo-dtp.yml` 中配置:

```yaml
platforms:
  - platform: ding
    urlKey: 你的钉钉机器人webhook的key
    secret: 你的钉钉机器人secret
    receivers: 18888888888  # 手机号,多个用逗号分隔
```

### 2. 配置企业微信

```yaml
platforms:
  - platform: wechat
    urlKey: 你的企业微信机器人webhook的key
    receivers: 接收人
```

### 3. 配置告警项

为每个线程池配置告警:

```yaml
notifyItems:
  - type: capacity        # 容量告警
    enabled: true
    threshold: 80         # 队列使用率达到80%告警
    interval: 120         # 告警间隔120秒
  - type: liveness        # 活性告警
    enabled: true
    threshold: 80         # 线程池活跃度达到80%告警
  - type: reject          # 拒绝告警
    enabled: true
    threshold: 1          # 有任务被拒绝就告警
  - type: run_timeout     # 运行超时告警
    enabled: true
    threshold: 5000       # 任务执行超过5秒告警
```

## 常见使用场景

### 场景1: 业务高峰期扩容

当业务高峰期来临，需要快速扩容线程池:

```bash
curl -X POST http://localhost:8080/threadPool/adjust \
  -H "Content-Type: application/json" \
  -d '{
    "threadPoolName": "execute-xxl-thread-pool",
    "corePoolSize": 10,
    "maximumPoolSize": 20,
    "keepAliveTime": 60
  }'
```

### 场景2: 业务低峰期缩容

业务低峰期，减少资源占用:

```bash
curl -X POST http://localhost:8080/threadPool/adjust \
  -H "Content-Type: application/json" \
  -d '{
    "threadPoolName": "execute-xxl-thread-pool",
    "corePoolSize": 2,
    "maximumPoolSize": 5,
    "keepAliveTime": 30
  }'
```

### 场景3: 批量调整多个线程池

```bash
curl -X POST http://localhost:8080/threadPool/batchAdjust \
  -H "Content-Type: application/json" \
  -d '[
    {
      "threadPoolName": "execute-xxl-thread-pool",
      "corePoolSize": 5,
      "maximumPoolSize": 10,
      "keepAliveTime": 60
    },
    {
      "threadPoolName": "austin.im.notice",
      "corePoolSize": 8,
      "maximumPoolSize": 12,
      "keepAliveTime": 50
    }
  ]'
```

## 监控指标说明

| 指标名称 | 说明 |
|---------|------|
| activeCount | 当前正在执行任务的线程数 |
| poolSize | 当前线程池中的线程总数 |
| largestPoolSize | 线程池曾经达到过的最大线程数 |
| completedTaskCount | 已完成的任务总数 |
| queueSize | 队列中等待执行的任务数 |
| queueRemainingCapacity | 队列剩余容量 |
| rejectCount | 被拒绝的任务数 |

## 注意事项

1. **参数约束**: 核心线程数必须小于等于最大线程数
2. **调整时机**: 建议在业务低峰期进行较大幅度的调整
3. **观察监控**: 调整后需要观察系统监控指标，确保系统稳定
4. **逐步调整**: 建议采用逐步调整的策略，避免一次性大幅度调整
5. **队列容量**: 某些队列类型不支持动态调整容量

## 故障排查

### 问题1: 调整后参数不生效

**排查步骤**:
1. 检查返回的响应是否成功
2. 查看应用日志，确认是否有错误信息
3. 确认线程池名称是否正确
4. 确认线程池是否已注册

### 问题2: 找不到线程池

**解决方法**:
1. 调用 `/threadPool/list` 查看所有已注册的线程池
2. 确认线程池是否已通过 `ThreadPoolUtils.register()` 注册

### 问题3: 参数校验失败

**常见原因**:
- 核心线程数大于最大线程数
- 参数值为负数
- 必填参数未填写
