# Austin 缓存防护快速配置指南

## 🚀 快速开始

本指南帮助你快速启用 Austin 项目的缓存防护功能。

---

## 📋 前置要求

1. ✅ Redis 服务已启动（版本 >= 3.0）
2. ✅ JDK 版本 1.8+
3. ✅ 项目已正确配置 Redis 连接

---

## ⚙️ 配置步骤

### 步骤 1: 检查依赖（已自动添加）

确认以下依赖已添加到 `austin-support/pom.xml`:

```xml
<dependency>
    <groupId>com.github.ben-manes.caffeine</groupId>
    <artifactId>caffeine</artifactId>
</dependency>
```

### 步骤 2: Redis 配置检查

确认 `application.yml` 或 `application.properties` 中 Redis 配置正确：

```yaml
spring:
  redis:
    host: localhost
    port: 6379
    password: your_password  # 如果有密码
    database: 0
    lettuce:
      pool:
        max-active: 8
        max-idle: 8
        min-idle: 0
```

### 步骤 3: 启用定时任务（可选）

如果希望使用缓存监控的定时打印功能，确保启用了 Spring 定时任务：

在 Spring Boot 启动类或配置类上添加：

```java
@EnableScheduling
public class AustinApplication {
    // ...
}
```

## 🔧 核心组件自动初始化

以下组件会在应用启动时自动初始化，**无需额外配置**：

| 组件 | 初始化时机 | 功能 |
|-----|----------|------|
| `LocalCacheManager` | @PostConstruct | 初始化 3 个本地缓存（account, template, apikey） |
| `CacheWarmupService` | @PostConstruct（延迟5秒） | 预热布隆过滤器和热点数据 |
| `CacheMonitor` | @Scheduled（每5分钟） | 打印缓存统计信息 |

## 🔍 常见问题

### Q1: 启动时报错 "Redis connection refused"

**A**: 检查 Redis 是否启动，并确认连接配置正确。

```bash
# Linux/Mac 检查 Redis 状态
redis-cli ping
# 应返回 PONG

# Windows 检查 Redis 状态
redis-cli.exe ping
```

### Q2: 看不到缓存预热日志

**A**: 缓存预热延迟 5 秒执行，请等待片刻。如果仍未看到，检查是否有异常日志。

### Q3: 本地缓存不生效

**A**: 检查 Caffeine 依赖是否正确引入：

```bash
mvn dependency:tree | grep caffeine
```

### Q4: 布隆过滤器误判率高

**A**: 当前配置误判率约 1%，如需调整：
- 增加哈希函数个数（修改 `BloomFilterManager.java` 中的 `getHash` 方法）
- 增加位数（修改 `getHash` 方法中的 `% 1000000`）

### Q5: 监控报告不显示

**A**: 确保启用了 `@EnableScheduling` 注解，并检查日志级别是否为 INFO。

## 🎨 可选配置

### 调整本地缓存大小

编辑 `LocalCacheManager.java`:

```java
// 修改最大容量
private static final int DEFAULT_MAXIMUM_SIZE = 20000; // 默认 10000

// 修改过期时间
private static final long DEFAULT_EXPIRE_AFTER_WRITE = 10L; // 默认 5 分钟
```

### 调整预热策略

编辑 `CacheWarmupService.java`:

```java
// 修改预热数量
int warmupCount = Math.min(templateList.size(), 200); // 默认 100
```

### 调整分布式锁参数

编辑 `DistributedLockUtil.java`:

```java
// 修改锁过期时间
private static final long DEFAULT_EXPIRE_TIME = 30L; // 默认 10 秒

// 修改获取锁超时
private static final long DEFAULT_TIMEOUT = 5L; // 默认 3 秒
```

## 📈 性能调优建议

### 1. Redis 连接池配置

高并发场景下，建议增大连接池：

```yaml
spring:
  redis:
    lettuce:
      pool:
        max-active: 20    # 默认 8
        max-idle: 10      # 默认 8
        min-idle: 5       # 默认 0
```

### 2. JVM 堆内存

本地缓存需要额外内存，建议调整：

```bash
java -Xms2g -Xmx4g -jar austin.jar
```

### 3. 监控告警阈值

根据实际业务调整 `CacheMonitor.java` 中的告警阈值：

```java
// 命中率低于 50% 告警（默认值，可调整为 60%、70% 等）
if (hitRate < 60 && stats.requestCount() > 100) {
    log.warn("Low hit rate! cache:{}, hitRate:{:.2f}%", cacheName, hitRate);
}
```

## 🛠️ 手动操作 API

如需手动操作缓存，可注入相关组件：

### 手动刷新布隆过滤器

```java
@Autowired
private CacheWarmupService cacheWarmupService;

// 刷新所有缓存
cacheWarmupService.warmupAllCache();

// 添加单个模板到布隆过滤器
cacheWarmupService.addTemplateToBloomFilter(templateId);

// 添加单个账号到布隆过滤器
cacheWarmupService.addAccountToBloomFilter(accountId);
```

### 手动清理缓存

```java
@Autowired
private LocalCacheManager localCacheManager;

// 清空指定缓存
localCacheManager.invalidateAll("account");

// 删除单个缓存项
localCacheManager.invalidate("account", "account:123");
```

### 手动查询缓存统计

```java
@Autowired
private CacheMonitor cacheMonitor;

// 获取所有缓存指标
Map<String, CacheMonitor.CacheMetrics> metrics = cacheMonitor.getAllMetrics();

// 检查健康状态
boolean isHealthy = cacheMonitor.checkHealth();
```
