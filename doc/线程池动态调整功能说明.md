# 线程池动态调整功能说明

## 功能概述

本项目已集成 `dynamic-tp` 动态线程池框架，实现了线程池参数的动态调整功能。支持通过 RESTful API 和 Apollo 配置中心两种方式进行线程池管理。

## 主要功能

### 1. 线程池信息查询

- **获取所有线程池信息**: `GET /threadPool/list`
- **获取指定线程池信息**: `GET /threadPool/get/{threadPoolName}`

返回信息包括:
- 线程池名称
- 核心线程数、最大线程数
- 队列容量、队列类型
- 拒绝策略
- 活跃线程数、当前线程数
- 已完成任务数、拒绝任务数
- 队列等待任务数等

### 2. 动态调整线程池参数

- **单个调整**: `POST /threadPool/adjust`
- **批量调整**: `POST /threadPool/batchAdjust`

支持调整的参数:
- `corePoolSize`: 核心线程数
- `maximumPoolSize`: 最大线程数
- `keepAliveTime`: 线程存活时间(秒)
- `queueCapacity`: 队列容量(部分支持)
- `rejectedHandlerType`: 拒绝策略

### 3. 监控告警

配置了多种监控告警类型:
- **容量报警**: 队列使用率超过阈值时报警
- **活性报警**: 线程池活跃度超过阈值时报警
- **拒绝报警**: 任务被拒绝时报警
- **变更通知**: 线程池配置变更时通知
- **运行超时报警**: 任务执行超时报警
- **队列等待超时报警**: 任务在队列等待超时报警

支持钉钉、企业微信等多种告警渠道。

## 使用示例

### 1. 查询所有线程池信息

```bash
curl -X GET http://localhost:8080/threadPool/list
```

### 2. 查询指定线程池

```bash
curl -X GET http://localhost:8080/threadPool/get/execute-xxl-thread-pool
```

### 3. 调整线程池参数

```bash
curl -X POST http://localhost:8080/threadPool/adjust \
  -H "Content-Type: application/json" \
  -d '{
    "threadPoolName": "execute-xxl-thread-pool",
    "corePoolSize": 5,
    "maximumPoolSize": 10,
    "keepAliveTime": 60
  }'
```

### 4. 批量调整

```bash
curl -X POST http://localhost:8080/threadPool/batchAdjust \
  -H "Content-Type: application/json" \
  -d '[
    {
      "threadPoolName": "execute-xxl-thread-pool",
      "corePoolSize": 5,
      "maximumPoolSize": 10,
      "keepAliveTime": 60
    },
    {
      "threadPoolName": "austin.im.notice",
      "corePoolSize": 8,
      "maximumPoolSize": 12,
      "keepAliveTime": 50
    }
  ]'
```

## Apollo 配置中心方式

除了 API 调整，也可以通过 Apollo 配置中心动态修改线程池参数。

### 配置文件位置

`austin-web/src/main/resources/dynamic-tp-apollo-dtp.yml`

### 配置说明

```yaml
spring:
  dynamic:
    tp:
      enabled: true
      enabledCollect: true          # 开启监控指标采集
      collectorType: micrometer     # 监控数据采集器类型
      monitorInterval: 5            # 监控时间间隔(秒)
      apollo:
        namespace: dynamic-tp-apollo-dtp.yml
      executors:
        - threadPoolName: austin.im.notice
          corePoolSize: 6
          maximumPoolSize: 8
          queueCapacity: 200
          queueType: VariableLinkedBlockingQueue
          rejectedHandlerType: CallerRunsPolicy
          keepAliveTime: 50
          allowCoreThreadTimeOut: false
          notifyItems:
            - type: capacity        # 容量报警
              enabled: true
              threshold: 80
              interval: 120
            - type: liveness        # 活性报警
              enabled: true
              threshold: 80
            - type: reject          # 拒绝报警
              enabled: true
              threshold: 1
```

### Apollo 配置变更流程

1. 在 Apollo 配置中心修改对应配置项
2. 发布配置
3. 应用自动接收配置变更
4. 线程池参数实时生效
5. 收到变更通知(如配置了告警渠道)

## 项目中的线程池

当前项目包含以下动态线程池:

### 1. execute-xxl-thread-pool
- **用途**: 接收xxl-job定时任务请求
- **默认配置**: 核心3线程, 最大3线程, 队列200

### 2. austin.{channel}.{type}
- **用途**: 处理各渠道各类型消息
- **示例**: austin.im.notice, austin.sms.marketing
- **默认配置**: 核心2线程, 最大2线程, 队列128

## 最佳实践

### 1. 参数调整建议

- **核心线程数**: 根据CPU核心数设置，通常为 CPU核心数 + 1
- **最大线程数**: 不超过核心线程数的2倍
- **队列容量**: 根据业务峰值设置，避免过大导致内存占用
- **存活时间**: 非核心线程空闲超时时间，通常30-60秒

### 2. 监控告警

- 容量告警阈值建议设置为 80%
- 活性告警阈值建议设置为 80%
- 拒绝告警阈值建议设置为 1(有拒绝就报警)
- 告警间隔建议 120 秒，避免告警风暴

### 3. 注意事项

1. 核心线程数不能大于最大线程数
2. 队列容量调整需谨慎，某些队列类型不支持动态调整
3. 建议在业务低峰期进行参数调整
4. 调整后密切关注系统监控指标
5. 重要调整建议先在测试环境验证

## 常见问题

### Q1: 调整后参数不生效?
A: 检查线程池名称是否正确，确认线程池是否已注册到动态线程池管理器。

### Q2: 如何查看当前有哪些线程池?
A: 调用 `/threadPool/list` 接口查看所有已注册的线程池。

### Q3: 队列容量无法调整?
A: 标准的LinkedBlockingQueue不支持动态调整容量，建议使用VariableLinkedBlockingQueue。

### Q4: 如何接入告警?
A: 在配置文件中配置platforms和notifyItems，支持钉钉、企业微信等渠道。
