# 线程池动态调整功能实现总结

## 实现概述

本次实现为 austin 消息推送平台添加了完善的线程池动态调整功能,基于已集成的 `dynamic-tp` 框架,提供了RESTful API和配置中心两种方式进行线程池管理。

## 实现内容

### 1. 核心功能模块

#### 1.1 线程池信息查询
- **ThreadPoolController** - 提供RESTful API接口
  - `GET /threadPool/list` - 获取所有线程池信息
  - `GET /threadPool/get/{threadPoolName}` - 获取指定线程池信息

#### 1.2 线程池参数动态调整
- **ThreadPoolManageService** - 线程池管理服务
  - 支持单个线程池参数调整
  - 支持批量线程池参数调整
  - 参数校验和安全检查

#### 1.3 数据传输对象
- **ThreadPoolVO** - 线程池信息展示对象,包含18个属性
  - 配置信息: 核心线程数、最大线程数、队列容量等
  - 运行状态: 活跃线程数、已完成任务数、拒绝任务数等
  
- **ThreadPoolAdjustVO** - 线程池参数调整请求对象
  - 支持参数校验(JSR-303)
  - 核心线程数、最大线程数等可调整参数

### 2. 监控告警增强

完善了 `dynamic-tp-apollo-dtp.yml` 配置文件,为两个线程池添加了完整的监控告警配置:

- **容量报警**: 队列使用率超过阈值(80%)时报警
- **活性报警**: 线程池活跃度超过阈值(80%)时报警  
- **拒绝报警**: 任务被拒绝时报警(阈值1)
- **变更通知**: 线程池配置变更时通知
- **运行超时报警**: 任务执行超过5秒报警
- **队列等待超时报警**: 任务在队列等待超过2秒报警

支持钉钉和企业微信两种告警渠道,可配置告警间隔(120秒)。

### 核心类说明

| 类名 | 位置 | 说明 |
|-----|------|------|
| ThreadPoolController | austin-web/controller | 线程池管理接口层 |
| ThreadPoolManageService | austin-web/service | 线程池管理服务层 |
| ThreadPoolVO | austin-web/vo | 线程池信息展示对象 |
| ThreadPoolAdjustVO | austin-web/vo | 线程池参数调整请求对象 |
| ThreadPoolUtils | austin-support/utils | 线程池工具类(已存在) |

### API接口列表

| 接口 | 方法 | 说明 |
|-----|------|------|
| /threadPool/list | GET | 获取所有线程池信息 |
| /threadPool/get/{name} | GET | 获取指定线程池信息 |
| /threadPool/adjust | POST | 动态调整线程池参数 |
| /threadPool/batchAdjust | POST | 批量调整线程池参数 |

## 使用场景

### 场景1: 业务高峰期快速扩容
```bash
curl -X POST http://localhost:8080/threadPool/adjust \
  -H "Content-Type: application/json" \
  -d '{
    "threadPoolName": "execute-xxl-thread-pool",
    "corePoolSize": 10,
    "maximumPoolSize": 20,
    "keepAliveTime": 60
  }'
```

### 场景2: 业务低峰期资源缩容
```bash
curl -X POST http://localhost:8080/threadPool/adjust \
  -H "Content-Type: application/json" \
  -d '{
    "threadPoolName": "execute-xxl-thread-pool",
    "corePoolSize": 2,
    "maximumPoolSize": 5,
    "keepAliveTime": 30
  }'
```

### 场景3: 批量调整多个线程池
适用于全系统性能调优或应对突发流量。

## 最佳实践建议

### 1. 参数调整建议
- **核心线程数**: CPU核心数 + 1
- **最大线程数**: 核心线程数的2倍以内
- **队列容量**: 根据业务峰值设置,避免过大
- **存活时间**: 30-60秒

### 2. 监控告警建议
- 容量告警阈值: 80%
- 活性告警阈值: 80%
- 拒绝告警阈值: 1(有拒绝就报警)
- 告警间隔: 120秒

### 3. 调整策略建议
- 在业务低峰期进行较大幅度调整
- 采用逐步调整策略,避免一次性大幅度变更
- 调整后密切观察系统监控指标
- 重要调整先在测试环境验证
